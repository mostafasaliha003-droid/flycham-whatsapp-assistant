# Air Arabia Abu Dhabi search correction — awaiting live validation

The reported customer problem is Abu Dhabi to Damascus returning no Air Arabia quote although the customer sees flights in the supplier portal.

## Findings

- Airport aliases and queue routing preserve AUH and put the requested Abu Dhabi Air Arabia search first. They do not silently replace it with Sharjah.
- `prepareSearch` previously forced Search G9 for all Air Arabia requests. The airline's official Damascus announcement identifies Abu Dhabi flights as 3L504/505. A synthetic DOM reproduction proves that the old code chooses G9 even when a 3L option is offered, or rejects a form offering only 3L. The actual current portal option labels and values still require signed-in observation; the reproduction is not live inventory evidence.
- Separately, production logs show the Air Arabia consumer blocked at 13:02:55 UTC on 25 October after an incomplete cold login. FlyCham continued. A process marked live does not establish a working Air Arabia session. This outage can itself explain missing Air Arabia comparisons.

## Prepared changes

For AUH on either end, select a uniquely enabled observed 3L option. If no explicit 3L label exists, allow only the uniquely observed normal Search All option. Never guess an option enum. Select the carrier before airport autocomplete; the supplier's cached `setDefaultSearchOption` proves that airport selection can change it to INT. If necessary, restore the observed intended option once through the normal UI, then revalidate route, dates, currency, passenger counts, trip radio, Economy and Normal booking values before Search. Ambiguous, changed or unavailable controls fail as unverified, not as proof that flights are absent. SHJ G9 and FlyCham XH behavior remain covered.

The Air Arabia adapter now captures safe supplier timestamp baselines before Search. Before reading result counts, it requires a fresh successful `latestResponse`, the same response's search parameters and flight arrays, and matching route, dates, passenger counts, currency and observed search-system value. Raw segment route chains, carrier/flight designators and source-grounded departure dates must match; selected flight references are checked again after selection and before price calculation. Shared flight references across alternative rows are permitted, but duplicates in a selected chain are rejected. Initial, stale, failed or mismatched responses remain unverified; only a completed matched successful empty response can establish no flights.

A separate narrow login recovery permits one normal protected-page navigation after partial sign-in, only if the selected trusted popup is fully observable, has visible sign-out evidence and has no visible login, OTP, CAPTCHA, denial, invalid-credentials, password-change or concurrent-session response. Both normal authenticated controls are still required. No credential resubmission, verification bypass or open retry loop is introduced. The original incident included an unavailable child frame; this strict recovery intentionally does not bypass that uncertainty or guarantee recovery for that exact state.

## Validation and release gate

869 automated tests pass. Focused identity/adapter/carrier tests pass 134/134; carrier/airport/adapter compatibility passes 145/145. Coverage includes AUH to Damascus and the reverse, Abu Dhabi to Aleppo, explicit 3L and observed Search All selection, the supplier's automatic INT reset, one-time normal reselection, disabled/ambiguous/foreign/reset forms, trip/class/booking-type mutation, unchanged SHJ/FlyCham behavior, stale SHJ/G9 results paired with AUH, response/array identity, dates, counts, currency, selected flight references and partial-login recovery. These are mocked or synthetic DOM tests, not a completed live supplier search.

Do not merge to a deployed branch or trigger a production rollout until the signed-in portal shows the actual carrier selector and the Abu Dhabi to Damascus query has been exercised. Check actual flight timings and the verified final quote/ancillary flow on dates from the customer's request or an explicitly identified quote-only test. No ticket issuance, payment, changed margins, paid plan, new browser pool or hotel-system change is authorized by this correction.

The new identity contract is grounded in the previously captured primary supplier `tabSearchFlight28102018.js`, whose static path was recorded by the worker. The cached supplier script assigns response parameters and timestamps even for some failed responses, so those alone are insufficient; the new guard also binds successful latestResponse and its arrays. A new anonymous retrieval returned HTTP 403, so compatibility with the current live portal is not claimed.

Strict limitations remain a release gate: mixed/unrecognized carrier rows and codeshares make the whole response unverified rather than silently quoting a subset; unknown date/reference formats and null flight-array models also remain unverified. A one-way searchParams.returnDate of null is supported, but an unproven null returnFlights array is not. Observe the current live model and exercise actual AUH and SHJ quotes, including the final ancillary/price flow, before allowing production. The guard is designed to avoid a wrong confirmed price; synthetic passing tests do not prove general live availability.
