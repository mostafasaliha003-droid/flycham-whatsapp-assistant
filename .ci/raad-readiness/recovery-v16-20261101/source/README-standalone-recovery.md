## ما تفعله الأداة

1. تتحقق من بايتات ملفات القاعدة الـ445 وأوضاع Git قبل النسخ.
2. تنسخ الملفات المدرجة في الفهرس فقط إلى مجلد جديد؛ لا تستبدل نسخة موجودة.
3. تستبدل الملفات الثلاثة وحدها بالبايتات المقروءة من الالتزام الثابت.
4. تقارن حجم كل ملف وGit blob ووضعه ببيانات الشجرة الفعلية، ثم تعيد حساب الشجرة وبصمة التطبيق.
5. تربط مجلد التبعيات الموجود خارج نسخة المصدر برابط محلي؛ لا تثبت حزماً ولا تنسخ حالة عملاء أو نماذج.
6. تنتج فهرساً جديداً للاستعادة وبيانات قراءة فعلية. لا تعيد اختراع فهرس الجولة المفقودة أو سجلات اختبارات مفقودة.

الأداة لا تستدعي GitHub بنفسها. `download-staging/repository-source-payloads.json` مدخل استعادة محلي ينتجه اتصال القراءة المصرح به، ويتضمن `commit` و`tree` و`gitRecords` و`payloads`. كل عنصر في `gitRecords` يحتوي `path, mode, sha, size`، وكل عنصر في `payloads` يحتوي `path, url, text`؛ `text` هو نص الملف الفعلي المفكوك بترميز UTF-8، وتتحقق الأداة من Git blob قبل قبوله. هذا المدخل يحتوي شيفرة التطبيق، ولذلك هو مستبعد من الحزمة.

## حدود إعادة الإنتاج

`recover-source.py` هو نفس مساعد الاستعادة الذي نُفذ بنجاح، دون تعديل بعد التنفيذ. مساراته مرتبطة بترتيب مساحة العمل المسجل في أعلى الملف، وليست واجهة CLI عامة. لإعادة التشغيل في مساحة أخرى يلزم إعداد ترتيب المدخلات نفسه أو مراجعة المسارات في نسخة جديدة من المساعد، مع تسجيل بصمتها الجديدة. لا تُشغّل فوق مجلد خرج موجود.

المدخلات الخارجية اللازمة: مصدر القاعدة الثابت وفهرسه، ردود Git للالتزام المحدد، ومجلد تبعيات موجود معتمد. لا تتضمن الحزمة هذه المدخلات، ولا تدّعي أن التنفيذ تم في بيئة أخرى أو أن تثبيت الحزم أُعيد.

مخرجات الجولة الفعلية موجودة في قائمة `evidence-only-export-allowlist.json` المنفصلة. تغيير مسار الخرج يغيّر بيانات الفهرس وبصمته؛ بصمة شجرة التطبيق المتوقعة تبقى ثابتة.

## الاستبعادات

لا تُرفق مجلد `download-staging`، أو نسخة التطبيق المستعادة، أو ملفات القاعدة، أو التبعيات، أو نموذج OCR، أو أسراراً، أو حالة عملاء. هذه أداة استعادة فقط؛ لا تشغّل اختبار تطبيق، ولا تفحص الأمان، ولا تنشر، ولا تتصل بواتساب أو الحكومة أو مزود نموذج.
